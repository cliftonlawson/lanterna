# Lanterna Frontend Scaffold Notes

The current React screen is a first-pass scaffold around the Claude design handoff. It is useful for layout, screen inventory, theme tokens, and interaction shape. It is not the final component model.

The design source of truth remains:

- `design_handoff_lanterna_dashboard/Lanterna Dashboard.dc.html`
- `design_handoff_lanterna_dashboard/screenshots/`
- `Lanterna_schema_spec.md`

## Known placeholders to remove during wiring

The gradient media blocks are placeholders only. They should disappear when real media components are wired.

Current placeholder locations:

- `src/pages/ClaudeDashboard.tsx`: `seedGalleries[].gradient`
- `src/pages/ClaudeDashboard.tsx`: `gradients`
- `src/pages/ClaudeDashboard.tsx`: gallery-card thumbnail backgrounds
- `src/pages/ClaudeDashboard.tsx`: video-card thumbnail backgrounds
- `src/pages/ClaudeDashboard.tsx`: photos masonry tiles generated by `Array.from({ length: 15 })`
- `src/pages/ClaudeDashboard.tsx`: client preview thumbnail strip
- `src/pages/ClaudeDashboard.tsx`: video drawer hero and filmstrip picker
- `src/pages/ClaudeDashboard.tsx`: upload queue filenames and progress values

Replacement target:

- Gallery cards should use `galleries.cover_video_id` or `galleries.cover_photo_id`, resolved through `videos.poster_r2_key`, `videos.web_copy_r2_key`, or `photos.r2_key`.
- Video cards should render real poster frames from `videos.poster_r2_key`, then fall back to a generated/processed poster once Cloudflare processing completes.
- Photo masonry should render real `photos` rows grouped by `albums`, preserving varied aspect ratios from `photos.width` and `photos.height`.
- The video drawer filmstrip should be backed by extracted frame candidates or uploaded custom thumbnail assets, not static color blocks.
- Upload queue rows should come from real selected files and then `upload_jobs` / `media_tasks`, not fixed filenames.
- Client preview thumbnails should use real gallery media and honor `gallery_design.featured_video_id`.

## Scaffold allowed for now

These can stay while the UI is being rebuilt against the design handoff:

- Demo-only gallery names, counts, and statuses.
- Demo-only toast behavior.
- Demo-only live-save text.
- Demo-only modal/drawer state.
- Static account and vendor profile values.
- Static storage allowance numbers.

The moment a screen gets real data wiring, replace the local seed data for that screen with schema-shaped view models. Do not keep demo gradients or fixed arrays beside live data because they will hide empty, loading, and error states.

## Build direction

Rebuild from the handoff screen by screen, then wire data. The current `ClaudeDashboard.tsx` can be used as a temporary staging file, but it should be split into real components before backend wiring:

- App shell and sidebar
- All Galleries
- Gallery Studio
- Photos tab
- Videos tab
- Design tabs
- Deliver tab
- Vendor Dashboard
- Account screen
- Upload queue
- Video detail drawer

Keep the mock visual pieces obviously mock until they are removed. If something comes from placeholder data, it should not look like a production media asset.
